# Features

Everything Talaash does, by area. To get it running, start with the [Quickstart](quickstart.md); for the day-to-day flow, see [Daily use](daily-use.md).

## Sources at a glance

| Source                                                                     | How it is read                                     | Key needed           | Setting                                    |
| -------------------------------------------------------------------------- | -------------------------------------------------- | -------------------- | ------------------------------------------ |
| Greenhouse, Lever, Ashby, Recruitee, Workable, SmartRecruiters (companies) | each platform's public job-board API               | no                   | `companies` (`ats` + `token`)              |
| Personio (companies, common in Germany and the Netherlands)                | each company's public XML job feed                 | no                   | `companies` with `"ats": "personio"`       |
| Workday career sites (`*.myworkdayjobs.com`)                               | Workday's public JSON search                       | no                   | `companies` with `"ats": "workday"`        |
| Himalayas, Remotive, RemoteOK, Jobicy                                      | public remote-job APIs                             | no                   | `remote.boards`, `remote.himalayasQueries` |
| Hacker News "Ask HN: Who is hiring?"                                       | the month's thread through the public HN API       | no                   | `remote.boards` (`hackernews`)             |
| Arbeitnow                                                                  | public API (mostly Germany; NL and remote kept)    | no                   | `remote.boards`                            |
| Adzuna                                                                     | official API (Netherlands index)                   | free `ADZUNA_*` keys | `adzuna`                                   |
| LinkedIn                                                                   | guest job search, no login, paced                  | no                   | `linkedin` (`enabled: false` turns it off) |
| Bayt, GulfTalent, NaukriGulf, any job page                                 | the Chrome extension or the Bayt bookmarklet       | no                   | in your browser                            |
| Anything else                                                              | `bot add` with the job as JSON, or a referral note | no                   | none                                       |

`npm run bot -- fetch` reads all of them (four at a time); the daily run does it every morning. Each one is described below.

## Job discovery

- **Company career boards** (about 50 companies in `config.json` → `companies`) via the public APIs of Greenhouse, Lever, Ashby, Recruitee, Workable, SmartRecruiters and Workday, and Personio's public XML feed.
- **Personio** (many German and Dutch employers): add a company with `"ats": "personio"` and its subdomain as the token (`"acme"` for `acme.jobs.personio.de`; a company on another Personio domain takes the whole host, `"acme.jobs.personio.com"`). `bot discover <name>` tries it too.
- **Remote job boards:** Himalayas (only jobs open to your remote-from country, `remote.fromCode`), Remotive, RemoteOK and Jobicy (the 100 newest remote engineering jobs; Jobicy asks to be credited, and every job links to its original Jobicy page).
- **Hacker News "Ask HN: Who is hiring?"** (`hackernews` in `remote.boards`): every top-level comment of the current month's thread, read through the public Algolia HN API. The header line ("Company | Role | Location | REMOTE (EU) | …") gives the company, the role and the location; the filters then decide as for any other job. Postings keep their comment's date, so they age out after `maxAgeDays` like any other (raise it to keep the whole month). The dead-link check cannot tell whether an HN job is filled, so it leaves these alone.
- **Workday career sites** (`*.myworkdayjobs.com`, used by many large UAE/Saudi employers): add a company with `"ats": "workday"` and `"token": "<tenant>/<wdN>/<site>"`, e.g. `acme/wd3/AcmeCareers` for `https://acme.wd3.myworkdayjobs.com/en-US/AcmeCareers`. Or pass that full URL to `bot discover`. Listings come from Workday's public JSON search (at most 500 per company); descriptions are only loaded for postings whose title, location (target country, remote or "N Locations") and age could pass the filters, at most 40 per company.
- **Arbeitnow** (free public API, mostly Germany): only Netherlands and remote postings are kept. On by default (`remote.boards`).
- **Adzuna** (official API, Netherlands index; Adzuna has no UAE or Saudi index): searches the LinkedIn keywords (or `adzuna.keywords`) in `adzuna.countries`, `adzuna.pagesPerSearch` pages of 50 each. It needs a free key you register yourself at developer.adzuna.com; put it in `.env` (see `.env.example`):

  ```
  ADZUNA_APP_ID=...
  ADZUNA_APP_KEY=...
  ```

  Without them Adzuna is skipped with one log line. Adzuna only returns a snippet of each description, so its keyword scores see less text.
- **LinkedIn** guest job search (no login, your account is never used). It covers onsite jobs in `linkedin.locations` and remote jobs searched from `linkedin.remoteFrom`. Requests are 1.2 s apart, and a 429 stops LinkedIn for the rest of that fetch, with no retries (a later fetch tries again). Be aware that LinkedIn offers no public job-search API, and scraping its guest search is against LinkedIn's terms of service and can get your IP rate-limited or blocked; set `linkedin.enabled: false` in `config.json` to leave LinkedIn out of `fetch` entirely.
- **Bayt** via a browser bookmarklet (`scripts/bayt-collect.js`), because Bayt blocks direct requests. You click it on bayt.com and it sends jobs to the dashboard's `/api/import`. The dashboard serves the collector with your own search keywords and countries from `config.json` and with a per-installation import token (`data/import-token`, generated on first use), which `/api/import` requires from job-site origins. That stops other scripts on those sites (ads, trackers) from posting jobs blindly; a script written to attack Talaash could still load the collector and read the token, so the token raises the bar rather than closing the door. The Chrome extension's own origin needs no token (prefer it over the bookmarklet if that matters to you).
- **Chrome extension** (`extension/`, see [extension/README.md](https://github.com/abdulrehmandar2234/talaash/blob/main/extension/README.md)): "Send to Talaash" from any job page (Bayt, GulfTalent, NaukriGulf, company sites), and an "Apply helper" side panel with the prepared CV, letter and answers to copy, also on the application page (Lever `/apply`, Ashby `/application`, Workday's steps). **Fill this form** types your name and contact details, the cover letter, drafted answers and the CV PDF into the form's empty fields (outlined in orange); on a page whose job is not in Talaash, **Fill profile + CV only** types just your contact details and default CV. Custom dropdowns, listboxes and Yes/No buttons are never typed into: empty ones are listed as "pick from the list". It never overwrites what you typed, never fills answers that need your input, and never clicks a button or submits: you check the form and submit it yourself. The dashboard's address (default port 3100) is an extension option.
- **Manual add** of any job as JSON (`bot add`), e.g. from GulfTalent or a referral.
- **Company discovery** (`bot discover <names> --add`) tries a company name on the seven ATS platforms that work by name (Greenhouse, Lever, Ashby, Recruitee, Workable, SmartRecruiters, Personio; a full myworkdayjobs.com URL tries Workday) and adds it to the config if it has jobs in your target countries.
- **Daily automatic fetch** at a time you choose, 09:00 by default (`dailyTime`; `bot daily`, started by launchd on macOS, a systemd timer or cron on Linux, Task Scheduler on Windows), followed by AI review of new matches, a desktop notification and a database backup. Each step has a time limit, so one that hangs cannot block the rest; logs rotate at 5 MB, the IND sponsor register refreshes itself when a week old, and old filtered postings are pruned ([details](daily-use.md#a-typical-day)).

## Filtering and scoring

Every posting is checked by `src/match.ts`. Jobs that fail a rule are kept with status `filtered` and a reason, so you can see why.

- **Location:** onsite jobs in the `config.json` → `countries`, plus remote jobs that can be done from your country (`remote.fromCode`): its name, its regions (such as South Asia or EMEA) and its time zone count as open, other countries and regions as closed ([Remote regions](configuration.md#remote-regions)). Remote jobs locked to other regions are skipped. "EMEA" or no region gets a warning flag.
- **Role:** engineering titles only. Other stacks (Java, Go, Python, ...), mobile, QA and management roles are excluded.
- **Language:** postings that require fluent Dutch, Arabic, German or French are skipped, unless your profile lists that language. "Arabic is a plus" only adds a warning.
- **Visa:** per target country, `needsVisa` says whether you need one (missing = yes; the country you live in never does). Where you do, `visa: "employer"` means the employer provides it, and `"ind-register"` (Netherlands) means the company must be on the IND recognised-sponsor register (`bot sponsors:update` refreshes it); "No sponsorship" and "must have right to work" postings are skipped. Where you do not, those rules are skipped.
- **Visa label on every job:** only the posting itself counts as an offer. Each job shows one of four labels:
  - **✓ Visa/relocation offered:** the posting says so.
  - **✓ No visa needed:** a remote job, or a country you may already work in.
  - **? Company can sponsor, posting does not say:** the company is an IND recognised sponsor.
  - **? Visa/relocation not mentioned:** the posting is silent. Many Gulf employers sponsor the work visa anyway, but some only hire people already in the country.

  Hover a label for the full note. The **Visa/relocation offered (or not needed)** filter on the job list shows only the first two kinds. The AI location check also marks a silent onsite posting `unclear`, not `yes`.
- **Age:** postings older than `maxAgeDays` (14) are skipped, and matching jobs expire automatically once they get older.
- **Keyword score:** a weighted match of the job's skills against yours (a skill counts as yours when `cv/master.json` lists it), with a `minScore` threshold. It also suggests which CV version fits.
- **AI review:** the AI (by default the local Claude CLI with model `haiku`; see [AI](ai.md) for an API key instead) reads each matching job together with your CV and returns a 0–100 score, a verdict (strong / good / stretch / poor), reasons, gaps and red flags (part-time, language, visa, region lock). A problem that would hit every job (a rejected key, no credit, Claude signed out) or 3 timeouts in a row stops `ai:score` at once with one line and exit 1.
- **Location check from the whole description:** the same review decides whether you can take the job from where you live (`yes` / `no` / `unclear`), reading the full description rather than only the location field: "US only", "must reside in…", "authorized to work in X without sponsorship", required time zones, or a description that names another country ("work remotely from Slovenia" on a Saudi listing). A `no` moves a matching job to **Filtered out** with the quoted reason (`location (AI): …`), and it stays there when jobs are re-scored; jobs you already acted on keep their status. An `unclear` adds a "Location unclear" flag to check. Himalayas jobs limited to time zones far from GMT+5 are filtered by the keyword rules already.
- **Instant alerts:** when the AI rates a job `strong`, `ai:score` (and so the daily fetch) shows a desktop notification right away (macOS, Linux with `notify-send`, Windows toast): one per job, or one grouped notification for more than three. Each job alerts once (`alerted_at`). With `terminal-notifier` installed (Homebrew), clicking it opens the job in the dashboard. Turn it off with `config.json` → `ai.alertStrong: false`.
- **Salary:** a salary range in the title or description (any currency in [`src/currencies.json`](https://github.com/abdulrehmandar2234/talaash/blob/main/src/currencies.json), the country → currency table: codes, symbols such as ₹, CA$ or zł, and words such as "dirhams"; "20k–25k", "up to", per month / per year / per hour, Dutch "bruto per maand", Indian "12 LPA", "₹18,00,000" and lakh / crore. A mark several currencies share, such as "Rs", follows the job's country, then yours for remote jobs, then the text; plain "$" is always USD) is stored with the job. Funding rounds, budgets, bonuses and years of experience are ignored, and an unclear amount is left out rather than guessed. Adzuna, Himalayas, RemoteOK and Lever give salary data of their own, which wins over the text. `rescore` fills it in for jobs already stored.
- **Dutch visa salary check:** a job in a country that uses the IND register (the Netherlands), where you need a visa, gets a flag when its posted salary cannot meet the IND's highly-skilled-migrant minimum for your age: €5,942 gross per month at 30 or over, €4,357 under 30 (2026, without holiday allowance; [IND](https://ind.nl/en/required-amounts-income-requirements)). A yearly salary counts as 12 months plus the 8% holiday allowance. "Salary below…" means even the top of the range is too low, so the employer cannot sponsor the visa at that pay; "salary range starts below…" means only its bottom is. Set your birth date (`birthDate`, **Birth date** on the Settings page) for the right amount on the day you turn 30; without it the stricter 30-or-over amount is used. The flag never filters a job out. The reduced criteria (after a Dutch degree) are not checked.
- **Duplicate grouping:** the same job found on several sites (company board, LinkedIn, Bayt, Himalayas) is shown once, with links to every copy.

## Application preparation

- **CV versions:** a default CV plus versions per stack cluster (`laravel`, `tall`, `laravel-vue`, `mern`, `pern`, `next-nest`, `backend-node`, `frontend-react`, `ai-fullstack`) and one-off custom CVs for a single job. Every PDF has the same filename (`config.json` → `cvFileName`), and the folder name identifies the version. Versions are reused and only rebuilt (`v2`, `v3`, ...) when the master CV, profiles or template change.
- **Cover letters:** written by the AI (letter model) from the job description and your CV, using only true facts and making no promises about salary, notice period or start date. They are signed with the name and contact in your profile. If AI fails, a template letter is used instead, built from your profile: its `coverLetter` sentences (introduction, a pitch per CV cluster, how you work, remote experience), where you live and your visa need. To change a letter, tell the AI what should change (`letter <id> --feedback "shorter"`, e.g. "less formal" or "more about one project"): it rewrites the current letter with the same rules, and if the feedback asks for something your CV does not show, it leaves it out and says so in a short note. Or edit the letter by hand on the job page.
- **CV summary for a job:** the AI (letter model) rewrites the summary at the top of your CV for one job, from your CV and the job description: 3–4 sentences, 50–90 words, in the voice of your current summary, with only facts from your CV (no new skills, years or numbers, no promises). `summary <id>` writes it, `summary <id> --feedback "…"` rewrites it like a letter, and `cv:tailor <id>` builds a one-off CV version with it (in a new `custom-<company-role>-v<N>` folder every time, so a CV you already sent is never overwritten) and makes it the job's CV.
- **CV headline for a job:** the AI (letter model) writes the line under your name for one job, from your CV and the job description: the role as the job names it where your CV supports that, at your CV's seniority, and 2–4 of the job's main technologies that your CV shows ("Senior Full Stack Engineer · Laravel, React & Node.js"), at most 90 characters. `headline <id>` writes it and `headline <id> --feedback "…"` rewrites it. It is checked in code like a revised CV's title: a headline that names a skill or number your master CV does not show is not stored. `cv:tailor <id>` uses the job's headline as the CV title and its summary, whichever of the two it has.
- **CV templates:** every CV can be rendered in one of three ATS-safe designs (one text column, real text, standard section names, no images or tables): **classic** (the original design, unchanged), **modern** (a teal name banner and accent colour, skills as short text lines) and **compact** (smaller font and tighter spacing, to fit more on one page). `config.json` → `cvTemplate` sets the default (missing = classic), and each job can use its own: `cv:template <id> <template>` (or **Apply template** on the job page) re-renders the job's CV as a new version, so a CV you may already have sent is never overwritten. `prepare`, `cv:tailor` and `custom` use the job's template. `cv:templates` lists them and `cv:preview <template> [--pdf]` shows your master CV in one.
- **Feedback on the generated CV:** `cv:feedback <id> --feedback "…"` (at most 1000 characters; "summary too generic", "put Laravel experience first", "too long, fit on one page", "skills order wrong") has the AI (letter model) revise the job's CV from the job description, your master CV and the job's current CV. It may only reorder, re-frame, shorten or select what `cv/master.json` has: the title and summary wording, the order and selection of skill groups, skills, bullets and projects. The reply is then checked in code (`src/cv/feedback.ts`): every employer, bullet, skill group, skill and project must match the master CV, a new title or summary may not name a skill or number the master does not have, and employers are never dropped. Anything else is left out and listed under the AI's note. The result is a new one-off version in the job's template, made the job's CV. `cv:review <id>` ("Suggest improvements") stores a short, honest AI review of the CV against the job (what is weak or missing, what to put first) that you can turn into feedback.
- **CV keyword check** (`bot ats <id>`, and on the job page): the job's skill keywords split into those the CV version shows near the top, those you have (in `cv/master.json`) but this version keeps further down, and real gaps that are not on your CV at all. Its folded heading also says how many are not on your CV. It names the CV version that shows the most of them. Gaps are never added on their own. On the job page each gap has an **I have this** checkbox, with an optional note for the AI ("used Docker for CI at my last job"): **Add to my CV and improve it for this job** (`cv:feedback <id> --add-skills "Docker,GraphQL" [--feedback "…"]`) adds only the ticked skills to `cv/master.json`, in the group that fits them (a copy of the file is kept in `data/cv-backups/` first), then the AI revises the job's CV so it shows them. Later CVs can show them too.
- **Form answers:** paste the questions from an application form and the AI drafts an answer for each one, using only your CV and `cv/applicant.json`. Personal decisions it cannot know (salary, notice period, start date) come back as `[FILL: ...]` and are highlighted. Each answer has a Copy button.
- **Interview prep:** for applied and interview jobs, the AI (letter model) writes likely technical questions with what to emphasise from your CV, behavioural questions with STAR stories built only from your CV, a short company brief from the posting alone (no web research, so unsure points are marked "verify before interview"), questions to ask them, and the job's key requirements mapped to your CV or marked as gaps. Everything has Copy buttons and a Regenerate button.
- **Follow-up reminders:** an `applied` job with no news for 7 days shows a "Follow up · N days" badge and appears in the **Needs follow-up** tab. On the job page, "Draft follow-up" has the AI write a short message (addressed to the job's recruiter or hiring manager contact if you added one, CV facts only), with a template fallback. You send it yourself and click "I sent a follow-up"; the reminder then waits another 7 days, and stops after 2 follow-ups. CLI: `follow-ups`, `follow-up <id>`, `followed-up <id>`.

## Tracking

- Statuses: `new` → `prepared` → `applied` → `interview` → `offer` / `rejected`, plus `skipped`, `expired` and `filtered`.
- Dead-link check: `bot check:open` asks each ATS API whether a posting still exists (Greenhouse, Lever, Recruitee, SmartRecruiters and Workday per posting; Ashby, Workable and Personio via the board list or feed; Himalayas through its search API, where a job found by its title counts as open; Hacker News jobs are left as unknown, since a comment stays up after the job is filled) and opens the page for other boards, where a 404/410, "no longer accepting applications" text or a redirect to a careers page means closed. Closed `new`/`prepared` jobs become `expired`; jobs you applied to keep their status and only show "Posting closed". Network errors, 5xx and rate limits never expire a job, and a LinkedIn 429 stops LinkedIn checks for that run. `prepare` checks first and stops on a closed posting (`--force` skips the check). The daily fetch checks up to 100 jobs not checked in 3 days. For a Himalayas job that is not closed it also looks the job up again (its pages answer bots with a 403, its search API does not): when its location changed after the fetch (e.g. from Worldwide to United States), it takes the new one and scores the job again, so a job no longer open to your country is filtered.
- Every status change is logged with an optional note (`job_events`), and every fetch is logged with counts and errors (`fetch_runs`).
- Free-text notes per job (recruiter name, contacts, follow-ups).
- **Contacts per job** (`bot contacts` / `contact:add`, and on the job page): recruiters, hiring managers and referrals, plus people you know at the same company, with a "ask for a referral before applying" reminder on jobs you have not applied to.
- **Skip reasons:** skipping a job asks why (`mark <id> skipped --reason stack|seniority|salary|location|company|language|other`, or the Skip button), and `/analytics` shows the patterns.
- **Database backup and restore:** the daily fetch keeps a `pg_dump` of the last 14 days in `data/backups/` (`bot backup`; gzip in Node, so only `pg_dump` is needed, on any OS). `bot restore <file>` loads one back with `psql`, in one transaction, after a fresh backup of the database it replaces ([how](troubleshooting.md#restore-a-backup)). Backups hold the database only, not `config.json`, `cv/` or `applications/`.

## Dashboard

```bash
npm run web          # http://localhost:3100
```

- It is for this computer only: it listens on 127.0.0.1, not on your Wi-Fi, and `web/proxy.ts` refuses any request whose Host is not localhost (so a web page cannot reach it through DNS rebinding). There is no login, so do not expose it.
- Tabs per status, search, country filter, minimum score and "best match first" sorting (AI score first, keyword score as fallback).
- Salary on each card ("AED 20k–25k / month") and a "Min salary" filter in any currency of `src/currencies.json` (your own country's currency by default), per month or year. It compares in euros per year with the fixed, approximate rates in that table. Jobs without a salary stay visible unless "only with salary" is ticked. When `cv/applicant.json` has `expectedSalary` for the job's country (a country code, or `remote`), a lower salary gets a "below your expectation" hint; it never hides the job. A plain number there is in the country's currency (USD for `remote`), per month in the Gulf and per year otherwise; text such as `"AED 25,000 per month"` or `"18 LPA"` says it itself.
- The list shows 10 jobs per page (25, 50 or 100 with the "per page" filter), with page links above and below it. The page links keep the tab, filters and sort; changing the tab or filters goes back to page 1.
- The Matching tab shows jobs posted in the last 24 hours unless **Posted within** says otherwise (any time, 3 or 7 days); the other tabs never hide a job for its age.
- Filters stay as you set them until you change them: a refresh, another tab, a job page and back, or opening the dashboard again keeps them (a cookie holds the last ones; `web/proxy.ts`, `web/lib/filter-memory.ts`). The search box, the tab and the page are not remembered. An empty list says how many jobs match without the filters and offers **Show any time** and **Reset filters** (`/?reset=1` forgets the remembered ones).
- Search (company or title) looks in **every tab**, and each card shows which tab it is in (Matching, Prepared, Applied, Skipped…). "Search only in _tab_" or a tab link narrows it to one tab.
- Per job: open the posting, **Prepare CV** (picks or builds the CV version), **Download CV**, AI review, and status buttons.
- **Keyboard triage** on the list: `j` / `k` (or the arrow keys) move a visible focus between the cards, `Enter` opens the posting, `o` the job page, `a` marks applied, `p` prepares the CV (or downloads it), and `s` moves into the card's skip-reason select (pick a reason, `Enter` skips, `Esc` backs out). `?` shows the list. The keys do nothing while you type in a search box or select, so the filters stay usable.
- **Bulk skip** (Matching and Prepared tabs): `x` (or shift-click for a range) selects cards, and the bar at the bottom skips them all at once with one optional reason, at most 100 per click; jobs that moved past triage meanwhile are left alone. `Esc` or **Clear** empties the selection.
- Job page: **← All jobs** goes back to the exact list you came from (tab, filters, search, page), with **Previous** / **Next** through it (they keep working after you mark the job applied or skip it); keys `j` / `k` (next / previous), `Esc` (back), `a` (applied) and `s` (skip reason), off while you type. History has **Undo** for the last status change (restores the applied date and skip reason). A status button from a stale tab is refused instead of moving the job back. Rewriting a letter, summary or headline you edited, and **Clear all** for drafted answers, ask first.
- Job page: "Check if still open" button, full description, CV keyword check, cover letter, form-answer helper, notes and status history. The cover letter is never written automatically: **Write letter** writes it (AI from the description, else the template), **Rewrite letter** writes a new one, **Copy** copies it, and **Download PDF** downloads it as a one-page PDF in the CV's style, with your name and contact as the header (`bot letter:pdf <id>`, saved as `cover-letter.pdf` in the job's `applications/` folder). Under the letter, **What should change?** with **Rewrite with feedback** has the AI rewrite it (`letter <id> --feedback`), and **Edit** lets you change it yourself and **Save** it with no AI (the label then says "edited by you").
- Job page, **CV for this job**: the CV version and its template, a template select with **Apply template** (a background task; previews of each template open in a new tab), **Download CV**, **What should change in this CV?** with **Improve CV with feedback** (`cv:feedback`), and **Suggest improvements** (`cv:review`) whose suggestions **Use as feedback** copies into the box. When a CV was revised with feedback, what was left out because your master CV does not have it is listed there. `GET /api/cv/preview/<template>` shows your master CV in a template (HTML, or `?pdf` for a PDF). The Settings page has the default **CV template**.
- Job page, **CV headline for this job**: **Write headline**, then **Rewrite headline**, **Copy**, **Use in my CV for this job**, **Edit** and **What should change?**, like the summary below it.
- Job page, **CV summary for this job** (next to the cover letter): **Write summary** has the AI write a CV summary for the job, then **Rewrite summary**, **Copy** and **Use in my CV for this job**, which builds a one-off CV with it (`cv:tailor`) so **Download CV** serves that one. It has the same **What should change?** and **Edit** as the letter. While the AI writes or the CV is built, a "Writing summary…" / "Building CV for this job…" note replaces the buttons. **Use in my CV for this job** puts the job's headline and summary in the CV, whichever it has.
- "Fetch new jobs" button and an "Add jobs from Bayt" section with the bookmarklet.
- **Settings** (`/settings`): your profile, the cover-letter sentences, form facts, the search and filter settings and the AI provider, validated with the same schemas as the CLI before they are saved.
- **Analytics** (`/analytics`): the application funnel, response rates per source, country, CV version and AI verdict, weekly activity, time to a reply, skip patterns and fetch health (recent fetches and the sources that failed).
- A first-run banner until your profile has a name, email, location, country code and languages.
- Day and night themes: the round button in the bottom-right corner switches them, and the choice is remembered in this browser. Until you use it, the dashboard follows your system's light or dark setting.
