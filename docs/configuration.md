# Configuration: `config.json` and environment variables

`config.json` decides which jobs Talaash looks for and how it judges them: target countries, company boards, job-title rules, remote rules, search keywords, the AI and the CV output. Environment variables in `.env` and `web/.env.local` hold the database connection, the API key and a few overrides.

## Editing and checking `config.json`

`config.json` is yours and never committed (it is in `.gitignore`). On the first run, the bot and the dashboard create it as a copy of `config.default.json`, the settings the repository ships. To start over, delete `config.json` (or copy `config.default.json` over it).

There are three ways to change it:

- `npm run bot -- setup` asks for the target countries, remote work, LinkedIn locations, the AI and the CV file name ([your-cv-and-profile.md](your-cv-and-profile.md#the-setup-wizard) lists its questions).
- The dashboard's **Settings** page (`/settings`) edits most keys. It does not edit `countries`, `companies`, `stacks`, `chromePath`, `cvFileName`, `adzuna`, `ai.concurrency`, `ai.claudePath`, `ai.api.responseFormat` or the older provider sections; edit those in the file or with the wizard.
- Any text editor. On Windows, write a backslash in a JSON string twice (`"C:\\Users\\<you>"`), or use forward slashes.

`config.json` is validated against the schemas in `src/settings.ts` on every start, so a typo stops the bot with the file and field name (for example `companies[3].ats`). A top-level key the bot does not know (for example `minscore` instead of `minScore`) is kept, but reported as a warning, by `settings:check` and on every start. Check the file without starting anything:

```bash
npm run bot -- settings:check --kind config --file config.json      # {"ok":true}
npm run bot -- settings:check --kind applicant --file cv/applicant.json
```

**After changing filters, run `npm run bot -- rescore`**: it re-applies the filters and the keyword score to every stored job without downloading anything.

## Presets

`presets/` holds ready-made starting points. `npm run bot -- setup` lists them and asks which to use (comma-separated; Enter keeps `config.json` as it is). A preset replaces only the keys it covers.

| Kind   | Preset        | What it sets                                                                                                                                        |
| ------ | ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Market | `gulf`        | The UAE and Saudi Arabia (employer visa), their LinkedIn locations and Gulf company boards (Careem, Tamara, Salla, Foodics, ...)                    |
| Market | `india`       | India's tech hubs (Bengaluru, Hyderabad, Pune, Delhi NCR, Mumbai, Chennai), Adzuna `in` and Indian boards (Groww, CRED, Swiggy, Meesho, Atlan, ...) |
| Market | `netherlands` | The Netherlands (IND-registered sponsors), Adzuna `nl` and Dutch or Netherlands-hiring boards (Adyen, Mollie, bol.com, Picnic, ...)                 |
| Market | `pakistan`    | Pakistan (no visa for citizens), onsite and hybrid, and Pakistani boards (Motive, Devsinc, Securiti, Educative, Tajir)                              |
| Stack  | `php-laravel` | LinkedIn keywords and remote queries for PHP / Laravel, `php`, `laravel` in `roleInclude`, and PHP / Laravel skill patterns and CV clusters         |
| Stack  | `javascript`  | Node.js, NestJS, React, Next.js, Vue and MERN keywords, `node`, `react` in `roleInclude`, and the JS / TS skill patterns and CV clusters            |
| Stack  | `python`      | Python, Django and FastAPI keywords and skill patterns, `python`, `django` in `roleInclude`, and takes `python` out of `roleExclude`                |

- **Markets** set `countries`, `linkedin.locations`, `adzuna.countries` and `companies` (the boards of every chosen market, each once). Your remote-from country and its rules are separate questions.
- **Stacks** set `linkedin.keywords`, `remote.himalayasQueries` and `roleInclude` (generic words such as engineer, developer, software, plus each stack's), and take out of `roleExclude` only the words a stack needs. The rest of `roleExclude` stays. They also write the chosen ids into `stacks`, so the keyword score looks for each stack's skills and picks its CV clusters (see [Filters and scoring](#filters-and-scoring)).
- `config.default.json` is the three markets with the `php-laravel` and `javascript` stacks; a test (`tests/presets.test.ts`) keeps them in step.
- A preset is a plain JSON file: add your own to `presets/markets/` or `presets/stacks/` with the same fields, and the wizard offers it. Pull requests with new markets or stacks are welcome.

In the tables below, "Default" is the value in `config.default.json` (the original owner's, shown as an example), not a value the code fills in, unless the cell says "missing =".

## How filtering and scoring work

Every posting goes through `scoreJob()` in `src/match.ts`, in this order. The first rule that fails stores the job with status `filtered` and the reason, which you see in the dashboard's **Filtered out** tab or with `npm run bot -- list --status filtered`.

1. **Remote or onsite.** A location containing `remote`, `anywhere`, `worldwide` or `work from home` is a remote job (when `remote.enabled`). Its region text is checked: a target country's `match` there makes it an onsite job in that country ("Remote — Dubai"); otherwise it must match the allow pattern, and is filtered when it does not (with a different reason when it matches the deny pattern). These patterns come from your country: see [Remote regions](#remote-regions). A description with strong "US-based only" or "must reside in the EU" style phrases is filtered too. An empty region, or one matching `remote.flag`, passes with a "confirm your country is OK" flag.
2. **Country.** Otherwise the location must match one target country's `match` (for remote or EMEA-style locations, also "based in / office in _country_" in the description), or the job is filtered as "location not in target countries".
3. **Title.** The title must match `roleInclude` and must not match `roleExclude`. Both are case-insensitive regular expressions tested against the **title only**.
4. **Age.** Postings older than `maxAgeDays` are filtered (re-checked on every fetch and rescore, so matching jobs drop out as they age). Unknown dates pass with a flag.
5. **Language.** "Fluent / native / required" Dutch, Arabic, German or French is filtered unless your profile's `languages` lists that language; "Dutch or Arabic is a plus" only adds a flag.
6. **Visa** (onsite in a country where you need one). "No sponsorship", "must have the right to work", "nationals only" and similar phrases are filtered. For `ind-register` countries the company must be on the Dutch IND register (run `npm run bot -- sponsors:update`) or the posting must offer visa or relocation support, otherwise it is filtered. Remote jobs and countries with `needsVisa: false` skip this step.
7. **Keyword score.** The bot looks for about 40 known skills in the title and description: the skills of your `stacks` presets (PHP, Laravel, Node.js, React, Django, ...; `skills` in `presets/stacks/*.json`) plus cross-stack ones that count for everyone (AWS, Docker, SQL, Python, Java, Go, ...; `BASE_SKILLS` in `src/match.ts`). A found skill counts as yours when your `cv/master.json` skills list it. The score is `matched weight / found weight × 100` (core skills weigh 2), capped at 50 when fewer than 3 skills match, minus 15 if the posting asks for more than 10 years, plus 5 for a senior / lead / staff title, minus 20 for a junior / entry title, clamped to 0–100. A posting with none of the known skills is filtered ("no recognisable tech stack"). Below `minScore` it is filtered.
8. **AI review** (later, `ai:score`): a 0–100 score, a verdict (strong / good / stretch / poor), reasons, gaps, red flags and a location check that reads the whole description. A location `no` moves the job to `filtered` with the quoted reason (`location (AI): ...`); an `unclear` adds a flag. The dashboard's "Best match first" sorts by the AI score, then the keyword score.

The skill list and the CV clusters follow your `stacks` (missing or empty = `php-laravel` and `javascript`). If no shipped stack preset matches yours, the keyword score sees fewer of your skills: add a preset with your stack's `skills` (and `clusters`, if you keep CV framings in `src/cv/profiles.ts`) to `presets/stacks/`, or lean on the AI score and keep `minScore` low.

**Visa label.** Every job also shows one of four labels, from the posting itself: **Visa/relocation offered** (the posting says so), **No visa needed** (remote, or a country where `needsVisa` is false or that is your own `countryCode`), **Company can sponsor, posting does not say** (an IND recognised sponsor) and **Visa/relocation not mentioned**.

### Salary currencies

Salaries are read and compared through [`src/currencies.json`](https://github.com/abdulrehmandar2234/talaash/blob/main/src/currencies.json), not `config.json`. Under `"countries"` it maps each country code to its currency (`"IN": "INR"`); under `"currencies"` each currency has an approximate EUR rate (`eur`), the `symbols` and `words` postings write it with, and optionally tuned plausibility `bands` per year / month / hour. A currency without bands is checked against a wide US-dollar range after conversion.

- **Add a country:** one line under `"countries"`. Add the currency too when the table does not have it yet.
- **Shared marks:** "Rs" (PKR, INR, LKR, NPR) or "riyal" (SAR, QAR) mean the currency of the job's country, else of your own country (`remote.fromCode`, else `countryCode`) for remote jobs, else the one the text points to (₹, INR, LPA, lakh point to INR), else the first currency in the table. Plain "$" is always USD; other dollars count when written as such (`CA$`, `A$`, `S$`).
- **Dashboard:** the "Min salary" filter lists every currency there and starts in your country's currency.
- The rates are fixed on purpose: good enough to filter, not for accounting. Update them in the file when they drift.

### Remote regions

A remote posting says where it is open: "Remote — Worldwide", "Remote, India", "EMEA", "GMT+5:30". The bot works out which of these include you from the country you work from (`remote.fromCode`, else your profile's `countryCode`), using a table of countries and regions in `src/regions.ts`:

- **Open:** worldwide words (`worldwide`, `anywhere`, `global`, `international`), your country's name, the regions it is in, and its time zone. For India: India, South Asia, Asia, APAC, IST and GMT+5:30. For Pakistan: Pakistan, South Asia, Asia, APAC, the Middle East / MENA / GCC, EMEA, PKT and GMT+5.
- **Limited to somewhere else:** every other country in the table, and every region your country is not in. A Pakistan-only job is filtered for someone in India, and an India-only job for someone in Pakistan.
- **Flagged:** "international", no region given, and EMEA for EMEA countries (open, but confirm before applying).
- A country that is not in the table gets worldwide jobs and jobs that name it (`remote.from`). Pull requests that add countries are welcome.

So changing `remote.from` / `remote.fromCode` (in the setup wizard or on the Settings page) is all a new user needs. Set `remote.allow`, `remote.deny` or `remote.flag` only to replace the computed pattern; leave them out (or empty on the Settings page) to go back to automatic.

## LinkedIn

LinkedIn is searched as a guest (no login, your account is never used), with requests 1.2 s apart. The number of list requests is (`locations` + 1 remote search) × `keywords` × `pagesPerSearch`, plus one request per new posting for its description. A 429 answer stops LinkedIn for the rest of the run, keeping what was fetched.

| Key                       | Type    | Default                                               | What it does                                                                                | Sensible value / when to change                           |
| ------------------------- | ------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `linkedin.enabled`        | boolean | `true`                                                | Include LinkedIn in `fetch`.                                                                | `false` while you are rate-limited.                       |
| `linkedin.keywords`       | list    | `laravel`, `php`, `node.js`, ...                      | One search per keyword per location. Also Adzuna's default keywords.                        | 4–8 keywords: your main frameworks and role names.        |
| `linkedin.locations`      | list    | `United Arab Emirates`, `Saudi Arabia`, `Netherlands` | Onsite search locations, as typed in LinkedIn's location box.                               | Your target countries (or cities).                        |
| `linkedin.remoteFrom`     | text    | `Pakistan`                                            | Location of the remote (`f_WT=2`) search; empty = no remote search. Needs `remote.enabled`. | Your country. The setup wizard sets it.                   |
| `linkedin.pagesPerSearch` | count   | `2`                                                   | 10 results per page.                                                                        | 1–3. More pages mean more requests and a higher 429 risk. |

## Regular expression tips

`roleInclude`, `roleExclude`, `countries.<code>.match`, `remote.allow`, `remote.deny` and `remote.flag` are JavaScript regular expressions, matched case-insensitively anywhere in the text.

- In JSON a backslash is written twice: `"\\bqa\\b"` means `\bqa\b`.
- Use `\b` around short words (`\\bgo\\b`, `\\bjava\\b`, `\\bml\\b`) so `go` does not match "Google" and `java` does not match "JavaScript".
- `.?` covers an optional character: `full.?stack` matches "fullstack", "full-stack" and "full stack".
- Try a pattern with Node (the same quoting works in bash, zsh and PowerShell):

  ```bash
  node -e "console.log(/full.?stack/i.test('Senior Full-Stack Engineer'))"
  ```

## Adzuna (optional section)

Adzuna is an official job-search API. Salaries it returns are read in each country's currency from `src/currencies.json`. It needs a free key you register yourself at [developer.adzuna.com](https://developer.adzuna.com), in `.env` as `ADZUNA_APP_ID` and `ADZUNA_APP_KEY`; without them the `adzuna` board is skipped with one log line. It only returns a snippet of each description, so its keyword scores see less text.

| ----------------------- | ---------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| `adzuna`                | object, optional | `{ "countries": ["nl"], "pagesPerSearch": 2 }` | Settings for the `adzuna` board. Missing = the defaults in the next rows.                                 |                                       |
| `adzuna.countries`      | list             | missing section = `["nl"]`                     | Adzuna country indexes (lower-case: `gb`, `us`, `de`, `nl`, `fr`, ...). Adzuna has no UAE or Saudi index. | Indexes for your targets.             |
| `adzuna.keywords`       | list, optional   | missing = `linkedin.keywords`                  | Search terms.                                                                                             |                                       |
| `adzuna.pagesPerSearch` | count            | missing section = `2`                          | 50 results per page.                                                                                      | 1–3 (the free plan has tight limits). |

| `autoCvVersions` | boolean                                      | `false`             | `true`: `prepare` picks the per-stack CV version a job fits. `false`: always the default CV unless you pass `--cv`.                                                                                                                              | Keep `false` until you have rewritten `src/cv/profiles.ts` for your CV ([why](your-cv-and-profile.md#cv-versions-and-the-per-stack-framings)). |
| `cvTemplate`     | `classic` \| `modern` \| `compact`, optional | missing = `classic` | The CV design for jobs that have no template of their own. The Settings page has it as **CV template**.                                                                                                                                          | Preview each with `npm run bot -- cv:preview <template> --pdf`.                                                                                |

The system Chrome paths tried by `auto`: on macOS `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` and `/Applications/Chromium.app/Contents/MacOS/Chromium`; on Windows `C:\Program Files\Google\Chrome\Application\chrome.exe` and the `(x86)` folder; on Linux `/usr/bin/google-chrome`, `/usr/bin/google-chrome-stable`, `/usr/bin/chromium` and `/usr/bin/chromium-browser`.

## Daily run

| Key         | Type                     | Default           | What it does                                                                                                                                                                                                                                                                                                                                 | Sensible values                          |
| ----------- | ------------------------ | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `dailyTime` | time `"HH:MM"`, optional | missing = `09:00` | When the scheduled daily run starts, local 24-hour time (`"18:30"`). On macOS and Linux the scheduler checks every 30 minutes (`bot daily --if-due`), so a new time works from the next check with no other change. On Windows the task starts at the time itself: run `schedule:print` again after changing it. The Settings page edits it. | Before you start your day, e.g. `08:00`. |

The run happens once a day: at `dailyTime`, or at the first check after it if the computer was asleep or off. Changing the time after today's run moves tomorrow's. `npm run bot -- daily` (without `--if-due`) always runs at once.
